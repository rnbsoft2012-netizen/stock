# 매일 아침 7시 카톡 브리핑 - 실행 절차

매일 아침 7시(KST)에 깨어나는 Claude Routine이 그대로 따라야 할 절차입니다.

## ⚠️ 먼저: 커넥터 3종을 켠 상태로 세션을 시작해야 한다

필요한 커넥터는 **PlayMCP**(카톡·네이버뉴스), **Zapier**(메일 발송),
**Gmail**(메일 초안 폴백) 셋이다.

커넥터 도구 목록은 **세션이 시작될 때** 확정된다. 대화 중간에 커넥터를 붙이면
당장은 도구가 붙지만, MCP 서버가 한 번 끊겼다 붙으면 사라지고 돌아오지 않는다
(아래 "대화 도중 추가한 커넥터는 오래가지 않는다" 참조). 게다가 세션은 자기가
가진 커넥터 집합을 **좁힐 수만 있고 넓힐 수는 없어서**, 커넥터 없이 시작한
세션에서 예약을 만들면 그 예약도 해당 커넥터를 쓸 수 없다.

따라서 발송과 아침 7시 예약 생성은 **커넥터 3종을 미리 켜둔 새 대화**에서
해야 한다. 붙여넣을 인수인계 프롬프트는 아래 "세션을 옮길 때 쓸 인수인계
프롬프트" 절에 있다.

### 예약(Routine): 커넥터를 가진 세션에 **바인딩**하면 세션 안에서도 만들 수 있다

**2026-08-06 최종 확인 (이 방법으로 만들었다).** 커넥터 3종을 켠 채 새 세션을
시작하고, 그 세션에서 `create_trigger`를 **`persist_session` 기본값(true)** 으로
호출하면 예약이 *그 세션 자체를 깨우는* 형태로 만들어진다. 만들어진 트리거는
`trig_01PtmBVsTdXdzAQu8Re3QfgY`(매일 `0 22 * * *` = 07:00 KST)이고,
`persistent_session_id`가 그 세션을 가리킨다.

`connectors` 파라미터는 여전히 조직 정책에 막혀 있어 넘기지 않았고, 그래서
생성 응답에는 `stores no MCP connectors` 경고가 붙는다. **다만 이 경고는
"새 세션을 만드는" 예약에 해당하는 이야기다.** 기존 세션에 바인딩된 예약은
새 세션을 만들지 않고 그 세션을 이어서 깨우므로, 그 세션이 시작 시점에 가진
커넥터를 그대로 쓴다 — 는 것이 아래 "커넥터는 세션 시작 시점에 확정된다"에서
따라 나오는 결론이다.

⚠️ **아직 실제 발화로는 검증되지 않았다.** 첫 발화는 2026-08-06 22:00 UTC다.
그날 아침 카톡이 오지 않으면 이 가정이 틀린 것이므로, 아래 Routines UI 방법으로
되돌아간다.

### (대안) claude.ai Routines UI에서 만들기

빼고 만들면 예약은 생성되지만 `stores no MCP connectors` 경고가 붙고, 그
예약이 깨우는 세션에는 `mcp__*` 도구가 아예 없어 카톡 전송이 불가능하다.

## 브리핑 형식 (확정)

카카오톡 메시지 1건은 **최대 200자**입니다. 보유 종목이 23개라 종목당 1건씩
보내면 매일 24건이 되므로, **요약 1건 + 주목 종목 5건 = 총 6건**으로 보냅니다.

- **요약(1건)**: 전체 평가금액·당일 등락·평가손익 + 계좌 A/B별 평가·손익.
  계좌는 요약에서만 나누고, 종목 설명은 두 계좌를 합산해 중복 없이 다룹니다.
- **주목 종목(5건)**: `scripts/brief.py`가 골라줍니다. 등락률 상위 3개 +
  거기 안 뽑힌 종목 중 하루 평가액 변동액 상위 2개. 작은 종목의 -18%와
  비중 큰 종목의 +5%를 둘 다 놓치지 않기 위한 조합입니다.
- 두 계좌에 걸친 종목(SK하이닉스, 현대모비스)은 평단가 차이가 크므로
  계좌별 평단·수익률을 함께 적습니다. `brief.py`의 `held_in`에 들어 있습니다.

## 전략 작성 규칙

각 종목 메시지의 마지막 줄은 `전략:` 한 줄입니다. **근거 있는 관점 정리이지,
투자 권유가 아닙니다.** 다음 규칙을 지킵니다.

**써도 되는 것** — 전부 관측된 숫자나 읽은 기사에 근거가 있는 것:
- **비중 관점**: `stat_line`의 `비중N%`. 한 종목이 포트폴리오의 큰 부분을
  차지하면 그 종목의 등락이 전체를 좌우한다는 사실을 짚는다. (2026-08-06
  기준 SK하이닉스가 39.1%로 압도적이다.)
- **평단 관점**: `held_in`의 계좌별 평단·수익률. 같은 종목이라도 계좌 A는
  +71%, 계좌 B는 -24%처럼 갈리면 "계좌별로 상황이 다르다"를 명시한다.
- **고점 대비 위치**: `stat_line`의 `52주고점-N%`. 반등인지 낙폭 과대인지
  판단할 재료로 제시한다.
- **뉴스의 성격 구분**: 개별 기업 이슈(실적·계약·임상 등)인지, 업종 전체
  수급인지, 지수 영향인지. 종목이 지수 ETF면 지수 요인임을 밝힌다.
- **근거가 없을 때의 솔직함**: "관련 뉴스 없음, 수급/지수 영향으로 보임".

**쓰면 안 되는 것**:
- 추측 목표가("8만원까지 간다"), 매수·매도 지시("지금 담아라", "익절해라")
- 기사에 없는 전망을 사실처럼 단정하는 표현
- 확률·수익률 예측 수치

즉 `전략:`은 "지금 이 종목이 내 포트폴리오에서 어떤 상태이고, 오늘 뉴스가
그 상태의 무엇을 건드렸는가"를 한 줄로 정리한 것입니다. 판단은 사람이
합니다. 마지막 메시지의 면책 문구는 반드시 유지합니다.

## 절차

1. `python scripts/brief.py` 실행. 다음이 나온다:
   - `summary_message`: 그대로 보낼 수 있는 요약 메시지 (길이도 함께 출력)
   - `notable`: 주목 종목 5개 — 종목명, `news_query`, `stat_line`, `held_in`,
     `weight_pct`(포트폴리오 내 비중), `vs_52w_high_pct`(52주 고점 대비)
   - `all_holdings`: 전 종목 수치 (참고용, 브리핑에는 안 넣음)
2. `notable` 5개 각각에 대해 PlayMCP 네이버뉴스 검색(`NaverSearch-search_news`)을
   `news_query`로 `sort=date`, `display=3` 호출.
3. 종목별 메시지를 작성한다. `stat_line`을 그대로 쓰고 뒤에 붙인다:
   - `뉴스:` 헤드라인 한 줄 (기사 제목의 HTML 태그 `<b>` 제거)
   - `전략:` 아래 "전략 작성 규칙"에 따라 한 줄.
4. 각 메시지 맨 앞에 `[n/6]` 순번을 붙인다. 마지막 메시지 끝에
   `* 투자 참고용이며 투자 권유가 아닙니다.` 를 덧붙인다.
5. **보내기 전에 길이를 검증한다.** 메시지 6개를 JSON 배열 파일로 저장하고
   `python scripts/brief.py --check <파일>` 실행. 200자 초과가 있으면
   해당 메시지를 줄여서 다시 검증한다.
6. PlayMCP 카카오톡 나에게 보내기(`KakaotalkChat-MemoChat`)로 [1/6]부터
   순서대로 6건 전송한다.
7. `scripts/report.py`로 전 종목 카드 리포트를 만들고 `scripts/compact_html.py`로
   본문을 줄인 뒤 rnbsoft2012@gmail.com 앞으로 보낸다 ("메일" 절 참조).
   **Zapier 도구가 있으면 실제 발송**하고, 없으면 Gmail 커넥터로 **초안 생성**으로
   대체한다. 둘 다 없으면 건너뛴다. 어느 쪽을 했는지 세션에 남긴다.
8. 전송 실패 시 원인을 파악해 재시도한다. PlayMCP가 이 세션에서 꺼져 있으면
   (`enabledInChat: false`) 전송이 불가능하므로, 그 사실을 세션에 남긴다.

## 메일: Zapier로 발송, 없으면 Gmail 초안

브리핑을 카톡과 **함께 rnbsoft2012@gmail.com 으로도** 보내달라는 요청에 따라
2026-08-06에 Gmail 커넥터와 Zapier 커넥터를 연결했다. **발송 경로는 Zapier다.**

- **Gmail 커넥터로는 발송할 수 없다.** `create_draft`, `update_draft`,
  `list_drafts`와 읽기·검색·라벨 도구뿐이다. 커넥터 설명 자체가
  "Draft replies, summarize threads, & search your inbox"다. 권한 설정 문제가
  아니라 설계이므로 조직 설정을 바꿔도 열리지 않는다.
- **Zapier 커넥터의 Gmail 액션에는 발송이 있다.** 공식 디렉터리 설명에도
  "Run workflows like sending emails"라고 적혀 있다.
- SMTP 직접 발송은 불가능하다. 이 환경에서 `smtp.gmail.com` 587/465 연결이
  차단되고, 앱 비밀번호를 둘 안전한 저장소도 없다.

### Zapier로 보내는 법

액션은 `enable_zapier_action`으로 이미 활성화해두었다
(`selected_api`: `GoogleMailV2CLIAPI`, `action`: `message`). Zapier 쪽에서
Google 계정 인증도 마쳤다. 호출은 `execute_zapier_write_action`으로 한다.

| 파라미터 | 값 |
| --- | --- |
| `to` | rnbsoft2012@gmail.com |
| `subject` | `report.py` 출력의 `subject` |
| `body` | `report.py` 출력의 `html` |
| `body_type` | `html` |

#### 본문은 `compact_html.py`로 줄여서 넘긴다 (2026-08-06 추가)

`report.py`가 만드는 HTML은 23종목 카드 때문에 **69.5KB**이고, 그중 59%가
910번 반복되는 인라인 `style` 속성이다(서로 다른 값은 44개뿐). 발송은 MCP 도구
호출의 `body` 파라미터로 이뤄지므로 본문 전체가 인자로 들어가야 하는데, 70KB는
한 번에 다루기 버겁고 옮기는 과정에서 깨질 위험도 있다.

`python scripts/compact_html.py report.json` 이 반복 스타일을 `<style>` 블록의
클래스로 접어 **40KB(57%)로 줄인다.** 텍스트 내용과 태그 수는 그대로다(스크립트가
변환 후 동치를 확인할 수 있게 만들어져 있다). 받는 쪽이 Gmail이고 Gmail은 본문 내
`<style>`을 지원하므로 보이는 모양도 같다.

#### 목표가 메모(`notes.json`)는 매일 새로 만든다

`notes.json`은 저장소에 없고 `/tmp`에 두면 컨테이너와 함께 사라진다. 2026-08-06
세션 이관 때 실제로 잃어버려서 23종목의 목표가를 네이버뉴스로 다시 확인해
재구성했다. **이게 정상 동작이다** — 목표가는 어차피 매일 갱신되어야 하고,
오래된 수치를 재사용하면 ×0.7 매수선이 현실과 어긋난다(케이엠더블유 사례: 6월
목표가 7만원인데 주가는 그 사이 반토막). 종목당 "<종목명> 목표주가"로 한 번씩
검색하고, 확인되지 않으면 **비워둔다.**

**Zapier 도구가 이 세션에 없으면** (MCP 서버가 끊기는 경우가 있다) 발송을
포기하지 말고 **Gmail 커넥터로 초안을 만든다** — `create_draft`에 `to`,
`subject`, `body`(html), `htmlBody`(html)를 넣는다. 초안은 Gmail
"임시보관함"에 쌓이므로 보내지 않고 읽기만 해도 된다. 어느 쪽을 했는지는
세션에 남긴다.

### 대화 도중 추가한 커넥터는 오래가지 않는다 (2026-08-06 확인)

Gmail과 Zapier를 대화 도중 연결했더니 **곧바로 도구가 붙어서 동작했다.** 그래서
"커넥터는 세션 시작 시점에만 로드된다"는 앞의 서술을 한 번 정정했었는데,
**그 정정이 틀렸다.** 원래 서술이 맞다.

관측된 패턴:

| 커넥터 | 세션 시작 시 보유 | MCP 재연결 후 |
| --- | --- | --- |
| PlayMCP | 있었음 | **매번 복구됨** |
| Gmail | 없었음(도중 추가) | 복구 안 됨 |
| Zapier | 없었음(도중 추가) | 복구 안 됨 |

이 세션은 하루 동안 MCP 서버가 여러 번 끊겼다 붙었다. 그때마다 PlayMCP는
돌아왔지만 도중에 추가한 두 개는 돌아오지 않았다. 계정 레벨은 셋 다 계속
`connected: true`였다 — 인증 문제가 아니다.

정리하면 **세션이 영구적으로 갖는 커넥터 집합은 세션 시작 시점에 확정된다.**
도중 추가는 컨테이너가 살아 있는 동안만 임시로 듣는다. 따라서 커넥터를 새로
붙였다면, 그 커넥터를 계속 쓸 세션은 **새로 시작해야 한다.**

트리거 생성 도구에 커넥터를 첨부하는 것은 별개로 여전히 조직 정책에 막혀 있다.

### 메일 본문 만들기 — 전 종목 카드 리포트

`scripts/report.py`가 만든다. 카톡은 200자 제한 때문에 주목 종목 5개만 다루지만
**메일은 보유 23종목 전부**를 종목당 카드 하나로 싣는다.

```bash
python scripts/brief.py > /tmp/brief.json
python scripts/report.py /tmp/notes.json /tmp/brief.json
```

**두 번째 인자(브리핑 JSON)를 반드시 넘긴다.** 생략하면 시세를 새로 조회하는데,
장이 열린 뒤에 실행하면 카톡으로 이미 보낸 숫자와 어긋난다. 같은 아침의 카톡과
메일은 같은 실행 결과를 써야 한다.

`notes.json`은 티커를 키로 하며, 값은 다음 필드다(전부 선택):

| 필드 | 내용 |
| --- | --- |
| `target_low` / `target_high` | 증권사 목표주가 범위(원). **출처가 있을 때만** |
| `target_source` | 증권사명·금액·날짜. 오래된 수치면 그 사실도 적는다 |
| `bull` | 【강세론】 — 실제 리포트·기사에 나온 근거 |
| `bear` | 【약세론】 — 하향 리포트, 과열 신호, 실적 우려 |
| `action` | ▶ 대응 — 현재가와 ×0.7 매수선·평단·비중의 관계 |
| `check` | ✓ 체크 — 앞으로 확인할 이벤트 |

카드에는 `×0.7 매수선`이 자동 계산된다(목표가 × 0.7). 사용자의 매수 검토
기준이다. 목표가가 없으면 이 줄도 나오지 않고 "컨센서스 확인 안 됨"으로 표시된다.

#### 목표가는 반드시 출처가 있어야 한다

`target_low`/`target_high`는 **네이버뉴스에서 확인한 증권사 목표주가만** 넣는다.
"<종목명> 목표주가"로 검색하면 대부분 나온다. 확인되지 않으면 **비워둔다** —
지어낸 목표가는 ×0.7 매수선까지 오염시켜 리포트 전체를 못 쓰게 만든다.
2026-08-06 기준 6종목(테크윙·엘앤씨바이오·오킨스전자·한국피아이엠과 ETF 2종)은
커버리지가 없어 비워두었다.

목표가가 오래된 경우(로보티즈 6월, 케이엠더블유 3월)에는 `target_source`에
날짜와 "재확인 필요"를 적어, 기계적으로 매수선을 적용하지 않도록 한다.

#### 계좌 A·B 구분

같은 종목을 두 계좌가 함께 들고 있으면 카드에 **A·B 중복** 배지가 붙고 계좌별
수량·평단·수익률·평가액이 나뉘어 표시된다. 2026-08-06 기준 SK하이닉스(A 평단
97.1만 / B 평단 221.2만)와 현대모비스가 해당한다. SK하이닉스처럼 평단이 2배
넘게 벌어진 종목은 `action`에서 계좌별로 상황이 다르다는 점을 반드시 짚는다.

## 데이터 소스에 대한 메모

- **시세**: 국내·해외 모두 Yahoo Finance chart API를 `requests`로 직접 호출.
  - `yfinance` 라이브러리는 쓰지 않는다. 내부적으로 curl_cffi로 브라우저 TLS
    지문을 위장하는데, 클라우드 세션의 보안 프록시가 그 연결을 리셋한다.
  - `pykrx`도 쓰지 않는다. 최신 pykrx(1.2.8)는 KRX 계정(KRX_ID/KRX_PW)
    로그인을 요구하는데, 클라우드 환경변수에는 안전한 비밀 저장소가 없어
    계정 비밀번호를 두기 적절하지 않다. Yahoo가 국내 종목도 원화로 제공한다.
  - **코스닥 종목의 `.KQ` 접미사를 짐작하지 말 것.** 코스닥 코드에 `.KS`를
    붙여도 Yahoo가 200을 주지만 전혀 다른 종목 데이터가 온다 (로보티즈는
    `.KS`로 22,400원 / `.KQ`로 242,000원). 종목 추가 시
    `python scripts/resolve_tickers.py --check-portfolio` 로 검증한다.
- **뉴스**: PlayMCP 네이버뉴스 검색. 해외 종목도 네이버를 쓴다 — Yahoo 뉴스
  검색은 티커와 무관한 기사를 섞어 내보낸다 (NVDA 검색에 SolarEdge 기사).
- **시간대**: 컨테이너는 UTC다. 아침 7시 KST는 UTC로 전날 22시이므로
  날짜 표기는 반드시 KST 기준(`today_kst()`)으로 한다.
